## Priority Rules (highest to lowest)

### SR-1 · Evaluation-script semantics determine blocking vs. advisory verdicts

**Applies to:** Any file-set field where the review verdict is REVIEW in S1/S2
but the evaluation script (S5) does not check that field.  
**Rationale:** `check_remote.py` defines what constitutes PASS or FAIL for the
task. If the script does not examine a field, its presence or absence cannot
affect the evaluation outcome. Such fields are resolved as `NOT_BLOCKING`
(advisory) rather than FAIL.  
**Effect:**
- `LICENSE` → NOT_BLOCKING (check_remote.py does not verify license presence)
- `.gitignore` → NOT_BLOCKING (check_remote.py does not verify .gitignore)
- `_pages/category-archive.html` → NOT_BLOCKING  
**Winner when invoked:** S5 (evaluation script logic) > S1/S2 REVIEW label.

---

### SR-2 · Later instance snapshot resolution supersedes earlier intermediate snapshot

**Applies to:** Any field where values differ between instance _5 (S1/S2) and
instance _6 (S3/S4) due to differing agent outcomes.  
**Rationale:** Instance snapshots represent independent agent runs on the same
task. A later, more complete review (S3/S4, 2026-04-12) that explicitly addresses
bootstrap failures provides more diagnostic authority than the earlier instance's
outcome alone. However, neither instance is authoritative over the other for
fields that are inherently instance-specific (namespace, task outcome).  
**Effect:** Fields such as `overall_task_verdict` and `destination_namespace` are
resolved as `INSTANCE-SPECIFIC` — the value is not a single canonical value but
depends on which agent ran the task.  
**Winner when invoked:** Combined narrative (S4) for instance-specific fields;
S1/S2 for fields describing instance _5 outcomes.

---

### SR-3 · Machine-verified audit data beats unverified counts

**Applies to:** Aggregate counts (total tasks in finalpool).  
**Rationale:** `readback_audit.md` (S6) was generated by mechanically comparing
`full_scope.csv` SHA values against the live Git tree with a 0-mismatch stamp.
Commit messages are written by humans and may reflect intermediate states.  
**Effect:** `total_task_count_in_finalpool` = 77 (from S6), not 67 (from finalpool
commit message), because 77 is the post-editorial-curation count and S6 is
machine-verified.  
**Winner when invoked:** S6 readback_audit > S7 boundary_review > commit message.

---

### SR-4 · Structured machine-readable field beats narrative / derived label

**Applies to:** File-set fields where a CSV column gives an explicit verdict and
a prose document (S2/S4) gives a longer but equivalent formulation.  
**Rationale:** A dedicated CSV column is unambiguous by design. Narrative
summaries may paraphrase or elaborate.  
**Sub-rules:**
- For instance _5 file verdicts: S1 explicit `review_verdict` column > S2 prose.
- For instance _6 file verdicts: S3 explicit `resolved_verdict` column > S4 narrative.  
**Winner when invoked:** S1/S3 CSV column > S2/S4 prose.

---

### SR-5 · Active README beats base-template README for project label

**Applies to:** `project_name` and `human_display_name`.  
**Rationale:** `README.md` (S8) is the currently maintained documentation. `README_BASE.md` (S9) is a legacy v2 template stub containing stale metadata (`BenchTaskCollv2`).  
**Winner when invoked:** S8 README.md > S9 README_BASE.md > GitHub repo name.

---

### SR-6 · Cross-instance agreement confirms no conflict

**Applies to:** Fields where S1 and S3 record the same value.  
**Rationale:** When two independently-produced review documents agree, that value is confirmed with no residual conflict.  
**Effect:** `upstream_template_tree_sha` = `4f52d97e`; `subject_name` = `Junteng Liu (jliugi@connect.ust.hk)`.  
**Winner when invoked:** Either S1 or S3 (they concur); S1 cited as primary.

## Tie-breaking rule

When two sources of equal rank conflict, prefer the **more specific / more recently
authored** value. When recency cannot be determined, prefer the **machine-readable
CSV column** over human prose. When specificity is also equal, prefer the source
closer to `finalpool` in the review pipeline.
